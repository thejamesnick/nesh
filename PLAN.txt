# Nesh Implementation Plan

## Phase 1: Foundation (Weeks 1-2)
**Goal**: Working lexer, parser, basic commands, and CLI

### Build:
- [x] Lexer: Tokenize keywords, identifiers, strings, numbers, operators
- [x] Parser: Build AST from tokens (recursive descent or Pratt parser)
- [x] Runtime: Basic executor for print, let, simple expressions
- [x] CLI: Basic nesh command that runs .nsh files
- [x] Standard Library: print, let

### Test:
- [x] Unit tests for lexer (tokenization accuracy)
- [x] Unit tests for parser (AST generation)
- [x] Integration tests: print "hello", let x = 5, print x
- [x] Manual testing: REPL basic functionality
- [x] Benchmark: Startup time for simple scripts

**Done when**: `nesh script.nsh` works for print/let basics

---

## Phase 2: Core Features (Weeks 3-4)
**Goal**: Control flow, functions, expanded stdlib

### Build:
- [ ] Control Flow: if/then/else/end, comparison operators
- [ ] Functions: fn name() ... end, return statements, parameters
- [ ] Standard Library: if, fn, basic string ops
- [ ] System Commands: any unknown command resolved from PATH (no `run` wrapper needed)
- [ ] CLI Enhancements: better error handling, help text

### Test:
- [ ] Unit tests for control flow execution
- [ ] Unit tests for function calls and scoping
- [ ] Integration tests: if statements, function definitions/calls
- [ ] Manual testing: complex scripts with nesting
- [ ] Benchmark: Loop performance, variable access speed

**Done when**: `nesh script.nsh` works with if/else and functions

---

## Phase 3: AI Integration & Polish (Weeks 5-6)
**Goal**: Structured APIs, error handling, REPL improvements

### Build:
- [ ] Error Handling: Better error messages, position tracking
- [ ] REPL: History, line editing, multi-line support
- [ ] Structured Output: JSON AST export option for AI consumption
- [ ] Standard Library: File operations, math functions, string manipulation
- [ ] Module System: Basic import/export (simple version)

### Test:
- [ ] Unit tests for error cases and reporting
- [ ] Integration tests: file I/O, math operations
- [ ] REPL testing: history, editing, tab completion (basic)
- [ ] API testing: Structured output validity
- [ ] Benchmark: Memory usage during execution, GC impact

**Done when**: REPL is usable and error messages are helpful
